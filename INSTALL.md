# Installing servtuner

servtuner installs as five Helm releases: cert-manager, CloudNativePG, Envoy Gateway, kube-prometheus-stack
and servtuner itself. Each is its own release, upgraded and rolled back on its own, and any prerequisite
your cluster already runs can be skipped. `deploy/helmfile.yaml.gotmpl` declares all five.

**Tools:** `helm` (3 or 4) and `helmfile` v1.8.5. For an install without internet access, also
`hauler` v2.1.2. Nothing else is needed on site: the install uses `helmfile sync`, which needs no Helm
plugin.

**Cluster:** Kubernetes 1.35 or newer, a default StorageClass, and for real benchmarks GPU nodes
with the NVIDIA device plugin.

## 1. Your values

servtuner's chart needs a few decisions only you can make: copy `deploy/helmfile/site-values.example.yaml`
to `deploy/site-values.yaml` and set the hostname, TLS and storage. Every value of
`deploy/helm/servtuner/values.yaml` may go there, and it wins over the environment's values.

The helmfile also installs servtuner's private CA (release `servtuner-issuer`, the `servtuner-ca`
ClusterIssuer) and a Gateway (release `servtuner-gateway`), and points the chart at both. Each is plain
manifests in `deploy/helmfile/manifests/`, its own release, and optional: with your own issuer or Gateway,
add `--state-values-set install.issuer=false,install.gateway=false` and name yours in the site values. On a
cluster without a load balancer, add `gateway.serviceType=ClusterIP` and reach the Gateway with
`kubectl port-forward`. If your own class names an `EnvoyProxy`, give it `mergeType: StrategicMerge`:
without it, it replaces Envoy Gateway's default, which is where the proxy image under your registry is set.

### Secrets come first

No secret ever goes in a values file, the helmfile or the release: values name a Kubernetes Secret,
and you create it before the install. The ones a site may need:

| Secret | Where | Keys | When |
|---|---|---|---|
| a registry pull secret, e.g. `regcred` (`kubernetes.io/dockerconfigjson`) | every namespace servtuner and its prerequisites run in | `.dockerconfigjson` | your registry needs a login to pull |
| TLS certificates (`kubernetes.io/tls`) | servtuner's namespace | `tls.crt`, `tls.key`, `ca.crt` | `tls.source: secret` instead of cert-manager |
| object store keys for model weights | the managed server's namespace | `access_key_id`, `secret_access_key` (names are yours) | weights streamed from S3 without pod identity |
| a Hugging Face token | the managed server's namespace | `token` | gated models from Hugging Face or a mirror |

servtuner's own first-admin setup token is generated by the chart into a Secret.

## 2. With internet access

Download `servtuner-deploy-<version>.tar.gz` from the GitHub Release and unpack it (or use a checkout at the
release tag). The chart's images are the published ones, `ghcr.io/servtuner/servtuner-*:<version>`.

```
helmfile -f deploy/helmfile.yaml.gotmpl -e eks sync     # or -e kind for a local kind cluster
```

## 3. Without internet access

You receive `servtuner-<version>.tar.zst` (and optionally `servtuner-vllm-<version>.tar.zst`,
`servtuner-sglang-<version>.tar.zst` for a managed SGLang, and `servtuner-model-<name>.tar.zst`), `SHA256SUMS`, `THIRD_PARTY_NOTICES` and this guide.

```
sha256sum -c SHA256SUMS
hauler store load -f servtuner-<version>.tar.zst
```

### 3a. Into your registry

Copy every image into your registry (Harbor, Artifactory, Quay, Nexus, ECR, …). Each image keeps its
path and only the registry host changes, so `quay.io/jetstack/cert-manager-controller:v1.21.1` becomes
`registry.corp:5000/jetstack/cert-manager-controller:v1.21.1`.

```
hauler login registry.corp:5000 -u <user> -p <password>   # if it needs one
hauler store copy registry://registry.corp:5000
```

Then unpack the deploy bundle (the helmfile, its values and every chart file) and install:

```
hauler store extract hauler/servtuner-deploy-<version>.tar.gz:latest
tar -xzf servtuner-deploy-<version>.tar.gz
cp my-site-values.yaml deploy/site-values.yaml
helmfile -f deploy/helmfile.yaml.gotmpl -e airgap \
  --state-values-set registry=registry.corp:5000 sync --skip-deps
```

If the registry needs credentials to pull, create a `kubernetes.io/dockerconfigjson` Secret named, say,
`regcred` in each namespace (cert-manager, cnpg-system, envoy-gateway-system, monitoring, and servtuner's)
and add `--state-values-set 'imagePullSecrets={regcred}'`.

### 3b. Without a registry (a single node, k3s, RKE2, kind)

Hauler can serve the archive as a read-only registry on port 5000:

```
hauler store serve registry          # keep it running during the install and while pods start
```

Point the nodes' container runtime at it. On k3s and RKE2, `/etc/rancher/{k3s,rke2}/registries.yaml`:

```yaml
mirrors:
  "<this-host>:5000":
    endpoint: ["http://<this-host>:5000"]
```

and install with `--state-values-set registry=<this-host>:5000`. On kind, `just e2e-airgap` shows the
whole setup (containerd's `config_path` and a `hosts.toml` per registry).

### 3c. Amazon EKS with ECR

- **Reaching ECR offline:** the nodes reach ECR through VPC endpoints: `com.amazonaws.<region>.ecr.api`,
  `com.amazonaws.<region>.ecr.dkr` and the S3 gateway endpoint (ECR keeps layers in S3).
- **Repositories:** ECR creates repositories on push only through a repository creation template
  applied for `CREATE_ON_PUSH`:

  ```
  aws ecr create-repository-creation-template --prefix ROOT --applied-for CREATE_ON_PUSH \
    --description "servtuner release images"
  ```

  Otherwise create each repository first (`aws ecr create-repository --repository-name jetstack/cert-manager-controller`, …).
- **Copy and install:**

  ```
  aws ecr get-login-password | hauler login <account>.dkr.ecr.<region>.amazonaws.com -u AWS --password-stdin
  hauler store copy registry://<account>.dkr.ecr.<region>.amazonaws.com
  helmfile -f deploy/helmfile.yaml.gotmpl -e airgap \
    --state-values-set registry=<account>.dkr.ecr.<region>.amazonaws.com sync --skip-deps
  ```

  EKS nodes pull from their own account's ECR with their node role, so no pull secret is needed.
- **Bundles in S3:** see `deploy/aws/README.md` (EKS Pod Identity, no keys).

## 4. Skipping a prerequisite

Any prerequisite your cluster already runs can be skipped:

```
--state-values-set install.certManager=false,install.prometheus=false
```

servtuner then uses yours: cert-manager's CRDs, the CloudNativePG operator, a Gateway API controller (or
an Ingress: `ingress.enabled` in your values), and your Prometheus (`prometheus.url` in your values).

## 5. Prices

servtuner carries no price data. Runs are priced from what you give it, in **Managed Servers → Prices**:

- **Infrastructure:** a price table of node types and GPU models. The AWS Price List is offered only
  with internet access.
- **Token prices** (routers in front of paid APIs): a datasheet in LiteLLM's model-price format.
  1. On any machine with internet access, download
     `https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json`.
  2. Upload it under **Token prices**, or `PUT /price-book/datasheet` with the file as the body.
     Alternatively, host it inside your network and give its URL under **Edit prices**.

  Each run keeps the copy it used, and its page says "prices as of" that date. To refresh, upload the
  new file: earlier runs keep their prices.
- **Given prices:** a saved target can carry its own prices per 1M tokens and needs no datasheet.

## 6. Models

A managed server downloads its model from Hugging Face. Without internet access, choose its **Weights**:

- **An internal mirror:** any Hugging Face mirror vLLM can reach (it sets `HF_ENDPOINT`).
- **A seeded claim:** a PVC you fill once from a model archive. vLLM then never reaches out
  (`HF_HUB_OFFLINE=1`), and servtuner never deletes the claim.
- **An object store:** safetensors someone already put in S3 (or GCS, or Azure Blob). vLLM streams
  them straight into GPU memory with its Run:ai Model Streamer (`--load-format runai_streamer`, in the
  stock vLLM image), so nothing is copied onto a volume first. For an S3-compatible store give its
  endpoint. Name a Secret holding the access keys, or leave it empty to use the pod's own identity
  (EKS Pod Identity, IRSA, GKE Workload Identity). The location holds the model's config and
  tokenizer files too, as Hugging Face lays them out.

To build a model archive on a connected machine, download the model into a Hugging Face cache, then:

```
just model-archive qwen2.5-0.5b ~/.cache/huggingface/hub ./LICENSE
```

It refuses gated models and licences that do not clearly allow redistribution.

To seed a claim from the archive, run this on site:

```
hauler store load -f servtuner-model-qwen2.5-0.5b.tar.zst
hauler store extract hauler/servtuner-model-qwen2.5-0.5b.tar.gz:latest
kubectl -n <namespace> apply -f my-claim.yaml            # a PVC, e.g. qwen-weights, big enough for the model
kubectl -n <namespace> run seed --image=<registry>/servtuner/servtuner-bench:<version> --restart=Never \
  --overrides='{"spec":{"containers":[{"name":"seed","image":"<registry>/servtuner/servtuner-bench:<version>","command":["sleep","3600"],"volumeMounts":[{"name":"w","mountPath":"/models"}]}],"volumes":[{"name":"w","persistentVolumeClaim":{"claimName":"qwen-weights"}}]}}'
kubectl -n <namespace> cp servtuner-model-qwen2.5-0.5b.tar.gz seed:/tmp/model.tar.gz
kubectl -n <namespace> exec seed -- sh -c 'mkdir -p /models/hf && tar -xzf /tmp/model.tar.gz -C /tmp && cp -r /tmp/model/hub/. /models/hf/'
kubectl -n <namespace> delete pod seed
```

The managed server reads the model from `/models/hf`, where vLLM's `--download-dir` points.

## 7. GPU kernels (FlashInfer)

vLLM's attention and sampling kernels come from FlashInfer, which looks for its precompiled kernels
(cubins and JIT modules) in what is installed and downloads any it lacks from NVIDIA's servers. Without
internet access every kernel must already be there:

- **The stock vLLM image** (`vllm/vllm-openai`, in the optional vLLM archive) already carries them:
  vLLM's image build installs FlashInfer's `flashinfer-cubin` and `flashinfer-jit-cache` wheels for
  every GPU architecture. Nothing to do.
- **A host target** (vLLM installed with pip, run by `servtuner launcher`), **or your own image**: build
  the release with `--with-flashinfer` (or `--sm sm90a` for only your GPUs) and install the wheels from
  `servtuner-flashinfer-<version>-<cuda>.tar.zst` into vLLM's Python environment:

  ```
  hauler store load -f servtuner-flashinfer-0.7.3-cu130.tar.zst
  hauler store extract hauler/servtuner-flashinfer-0.7.3-cu130.tar.gz:latest
  tar -xzf servtuner-flashinfer-0.7.3-cu130.tar.gz && cd flashinfer && sha256sum -c wheels/SHA256SUMS
  pip install --no-index --no-deps wheels/flashinfer_cubin-*.whl wheels/flashinfer_jit_cache_sm80-*.whl
  ```

  The versions must match the FlashInfer your vLLM uses (0.7.3 for vLLM v0.34.0); a mismatched
  `flashinfer-cubin` is ignored and FlashInfer falls back to downloading.
- **A mirror instead:** copy FlashInfer's kernel repository inside your network and set
  `FLASHINFER_CUBINS_REPOSITORY` to it in the managed server's environment.

On an offline install servtuner sets `FLASHINFER_NO_DOWNLOAD=1` for every managed server, so a missing
kernel fails the boot at once and the target's page says which wheel to install, instead of the boot
hanging on a download.

## 8. Upgrades

Repeat the air-gapped install with the next archive: `hauler store load`, `hauler store copy`, unpack the new deploy
bundle, and `helmfile … sync`. The api migrates its database on start. Every release is an ordinary
Helm release, so `helm history` and `helm rollback` work on each, and a prerequisite can be held at
its version with `--selector name=servtuner` (only servtuner) while you upgrade the rest later.

## 9. Checking the install

- `helmfile -f deploy/helmfile.yaml.gotmpl -e airgap list`: the five releases and their versions.
- `kubectl get pods -A -o jsonpath='{..image}' | tr ' ' '\n' | sort -u`: every image should come from
  your registry.
- Open servtuner, create the first admin with the setup token, and run the mock or your
  own target.
